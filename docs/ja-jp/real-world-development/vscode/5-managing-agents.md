GitHub Copilot をエージェントモードにすると、コードベースを調査し、変更を提案し、ファイルを編集し、コマンドを実行して自律的に作業します。作業はリアルタイムでこのコンピューター上で行われるため、VS Code の Copilot Chat では、すべてのツール呼び出しとファイル編集をその場で確認できます。各差分をインラインでレビューし、個々の変更を受け入れるか却下するかを選択し、フォローアッププロンプトで会話の方向を調整して、作業をエディターから離れずに修正または拡張できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッションの途中でエージェントの方向を調整し、ハイコントラストモードにライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業が進行中に、デザインチームから追加の要望が届きました。既定のテーマが暗すぎるユーザー向けに、ライトモードの切り替えも欲しいとのことです。ゼロから新しい会話を始める代わりに、既存のセッションを方向付けして作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各ステップが表示されます。調査したファイル、実行したコマンド、提案した編集です。各ファイルの編集は、差分と **Keep** / **Undo** コントロールとともにチャット内にインラインで表示されます。

1. 演習 4 から Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しの結果を確認します。ファイルの読み取り、ファイルの編集、エージェントが実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案したら、インラインに差分が表示されます。
    - 変更を受け入れるには **Keep** を選択します。
    - 変更を取り消してエージェントに別の方法を試させるには **Undo** を選択します。
4. チャット上部の **Files changed** インジケーターを開き、このセッションでエージェントが変更したファイルの一覧全体を確認することもできます。

> [!NOTE]
> ツール呼び出しで権限が必要な場合（たとえばターミナルコマンドの実行など）、エージェントは作業を一時停止し、**Allow** プロンプトを表示します。実行してかまわないと判断したコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。完了メッセージには、エージェントが行った変更の要約が表示されます。

## エージェントの方向を調整してライトモードを追加する

ハイコントラストモードが実装されたので、同じ会話を続けてライトモードの切り替えを追加します。同じチャットセッションを継続しているため、エージェントには、変更したコンポーネント、使用したスタイル方法、設定したローカルストレージのパターンなど、以前の作業に関するコンテキストが保持されます。

1. Copilot Chat の入力欄に、次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは中断した作業を引き継ぎ、すでに行った変更を調査し、ライトモードの追加案を提示します。
3. ハイコントラストモードの確認時と同様に、反映される新しい編集をそれぞれ確認します。各差分で **Keep** または **Undo** を使用します。
4. エージェントが望ましくない方向に進んだ場合（たとえば、好まない形で切り替え UI をリファクタリングしようとした場合）は、チャット入力欄の横にある **Stop** ボタンで作業を停止し、明確化のフォローアップメッセージを送信できます。

> [!TIP]
> 進行中のセッションを方向付けするほうが、ゼロからやり直すより高速です。フォローアッププロンプトを使って調整を依頼できます（「CSS を簡素化し、セレクターを重複させる代わりに CSS 変数を使用してください」）、方向を修正できます（「3 番目の切り替えは追加せず、既存の設定パネルにライトモードを統合してください」）、または範囲を拡張できます（「両方の切り替えにキーボードショートカットも追加してください」）。

## 作業セットを確認する

変更をコミットする前に、エージェントが変更した内容を簡単に確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストの更新が表示されます。
3. 変更されたファイルをいくつか開いて差分を確認します。カスタムエージェントのアクセシビリティパターン（ARIA 属性、キーボードナビゲーション、セマンティック HTML、ローカルストレージによる永続化）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。[次のレッスン][next-lesson]で変更を公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使用して進行中のセッションを監視し、方向を調整しました。各ファイルの編集が反映されるたびにレビューし、変更を受け入れるか却下するかを選択し、フォローアッププロンプトでコンテキストを失うことなく作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を受け入れるか却下する方法。
- フォローアッププロンプトでセッションの途中に方向を調整する方法。

[次のレッスン][next-lesson]では、アクセシビリティ関連の作業をプルリクエストとして公開し、このラボ全体を通してローカルカスタムエージェントが生成した変更を確認します。
